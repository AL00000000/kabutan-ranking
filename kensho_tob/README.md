# TOBされた会社のPBRを調べる

## 何を確かめたいか

東証のPBR1倍割れ是正要請で「市場に評価されないくらいなら買収された方がいい」と
考える会社が増えているなら、**TOBされる会社のPBRは低いはず**。もしそうなら、
低PBR株を事前に仕込んで決算をまたぐ持ち方に意味が出る。

## 手順（スクリプトの順番）

| # | スクリプト | やること | 出力 |
|---|---|---|---|
| 1 | `fetch_tob_list.py --from 2024-01-01 --to <today>` | TDnetを1日ずつ舐めて「公開買付」を含む開示を貯める | `raw_tob.json` |
| 2 | `resolve_targets.py --since 2024-01-01` | 候補コードごとにTDnetを引き直し、対象会社と**初回公表日**を確定 | `targets.json` |
| 3 | `fetch_pbr.py` | IRBANKから公表直前の終値・PBRを取る | `pbr.json` |
| 4 | `build_sectors.py` | コード→33業種の対応表（過去の東証一覧も使う） | `sectors.json` |
| 5 | `fetch_jpx_perpbr.py` | JPXの月次「規模別・業種別PER・PBR」 | `jpx_perpbr.json` |
| 6 | `fetch_control.py` | 対照群（普通の上場企業300社）のPBR | `control.json` |
| 7 | `analyze.py` | 集計 | 画面 / `summary.json` |

## 落とし穴（どれも数字が狂う）

- **初回公表日を後ろにずらすと株価がTOB価格に張り付く。** 続報の日付で拾うと
  PBRが実態より高く出る（ベネ・ワンを続報の日で取ると13.82倍になった）。
  だから日別クロールだけで済ませず、会社単位で引き直して最古の当事者開示を採る。
- **初回開示のタイトルに「公開買付」が入らない案件がある。**
  例: スノーピーク「ＭＢＯの実施及び応募の推奨に関するお知らせ」。
  会社単位の引き直しでは `ＭＢＯの実施|非公開化|当社株式に対する公開買付` も拾う。
- **上場廃止すると株探もYahooも消える。** IRBANKは残る。
  `https://irbank.net/{code}/chart?y=YYYY-MM-DD` がその日を末尾とする約100営業日分の
  日足＋PBRを返す。
- **東証の取引終了は2024年11月5日から15:30。** 公表が引け後かどうかの判定に効く。
  引け後なら当日終値、場中なら前営業日の終値を使う。
- **yanoshinのTDnet APIは日によって `{"Tdnet": {...}}` とフラットの2形式で返る。**
  片方しか見ないとその日が丸ごと落ちる。
- **JPXの月次PBRは小数1桁まで**しかないので、業種相対PBRもその精度でしか出せない。
  分母が業種の「平均」であって中央値ではない点にも注意（高PBR銘柄に引っ張られる）。
- **自己株TOB（自社株買い）は買収ではない**ので除く。
  「公開買付けに準ずる行為として政令で定める買集め行為」も別物。

## 外れ値の扱い

素の平均はグロースの高PBR銘柄に引っ張られるので、4通り並べる。

1. 中央値・トリム平均（上下10%除外）
2. 高PBR業種を除いた集計
3. **業種相対PBR** = 各社PBR ÷ 同月・同市場・同33業種の平均PBR（JPX）
4. **対照群との比較** — 普通の上場企業300社の同時期PBR。
   TOB群が1.0倍でも市場が1.1倍なら差はほぼ無い、という判定のため。
